# Local serving and replay study

The user authorised implementation and long-running local GPU experiments on 2026-11-09. This study measures complete aspect–sentiment classification requests, using the existing Qwen3-4B model and frozen candidate definitions, demonstrations and thresholds. It does not modify the dissertation's scientific results or claim production deployment.

The three systems are frozen Qwen few-shot detection and sentiment, QLoRA detection and sentiment, and frozen Qwen few-shot detection followed by QLoRA sentiment. The first registered L2 fold is fixed before measurements. Its held-out aspect is not represented in the adapter's training labels. A fold is an evaluation configuration, not an aspect-specific expert. Quality on this replay cannot inherit the twelve-fold mean from the dissertation.

The complete preregistration is `configs/experiments/serving_replay_20261109.json`. Existing validation reviews are deterministically divided into 100 development inputs and 957 evaluation inputs, with separate label files. Both partitions have historical validation exposure and must be described as engineering replay. Official test data is not opened for new tuning. Thresholds stay frozen, and no new model training is planned unless artifact checks reveal a concrete need.

Implementation proceeds through artifact integrity and dependency inspection, conditional-inference correctness, loopback HTTP serving, development-only runtime configuration selection, fixed evaluation replay, repeated load tests, sustained-load and burst recovery tests, and delayed-label monitoring. Every expanded run records its exact arguments and output path before execution. The primary timing unit includes the complete twelve-candidate task. Failed, rejected and timed-out requests remain in the denominator.

The HTTP process keeps one model resident and serialises GPU work. Request batching may combine work across reviews while preserving per-request identity. Adapter state changes happen only within this worker. Real inference is required for performance measurements; prediction caches are reference evidence only. Cold model startup is reported separately.

Source and aggregate evidence will be checked and committed on the task branch. Raw reviews, labels, row-level outputs and model files stay in ignored local directories. The final report must distinguish measured service performance, proxy drift signals and label-derived model quality.
