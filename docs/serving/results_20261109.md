# Local Chattermill API results: study 20261109

This study measured the frozen two-stage Qwen workflow as a genuine loopback HTTP service on 9-10 November 2026. One request processes a complete review against all twelve candidate aspects, then classifies sentiment only for detected aspects. It is a local engineering replay, with no production customer traffic or measured business benefit.

The deployed fold is l2-a01, whose adaptation-training partition excludes reviews containing Account management: Account access. The historical validation split was deterministically separated into 100 development reviews and 957 evaluation reviews. Both subsets had already been exposed in historical selection: this is not a new blind model test. The official test split was not opened for this serving study. The historical 0.5075 result is an equal-weight mean of held-out pair micro-F1 across twelve separately evaluated folds, not a directly comparable overall service score. These results concern the historical Qwen pipeline, not subsequent DeBERTa experiments.

## Conditions and definitions

- NVIDIA GeForce RTX 5050 Laptop GPU; Windows; device-reported memory 8546484224 bytes (approximately 8 GiB). Python 3.13.11; PyTorch 2.10.0+cu128, Transformers 4.57.6, PEFT 0.19.1, bitsandbytes 0.49.2.
- Qwen3-4B-Instruct-2507 revision cdbee75f17c01a7cc42f958dc650907174af0554; NF4 double quantization with float16 compute. One resident base model and one shared two-task adapter, serialised by one GPU worker.
- Few-shot uses frozen demonstrations for both stages; QLoRA enables the selected adapter for both; Hybrid uses few-shot detection and adapted sentiment. Thresholds remain frozen. These are whole-pipeline comparisons with different prompts/limits/thresholds, not isolated weight-only causal tests.
- Candidate microbatch 4; token budget 4096; request batch 1; queue capacity 8; server/client deadlines 120/130 seconds. Prompt limits are 1024 tokens for few-shot and 384 for adapted scoring. Three warm-up requests and loading/startup are excluded from reported steady-state latency.
- Scoring reads restricted candidate-label logits, rather than generating a chat response. No query or answer-response cache is used. The prefix-on policy affects only few-shot stages; QLoRA-on is the common policy label and does not imply cache use by its adapted stages.
- HTTP percentiles describe successful attempts from actual send to full JSON response. The two-second budget starts at scheduled arrival and retains every attempt, including failures/unsent drops. Throughput counts completed review operations over wall time including drain; repeated operations are not new independent reviews.

## Frozen evaluation quality

All five quality runs attempted the same 957 unique reviews once and returned 957 successful responses. Main results use successful_only; paired contrasts use the common-success subset. F1 values below use the 0-100 scale. Presence counts review-aspect assignments; pair F1 requires both aspect and sentiment. Neither is whole-review accuracy.

| Configuration | Overall pair F1 | Seen pair F1 | Held-out pair F1 | Overall presence F1 |
| --- | --- | --- | --- | --- |
| few_shot_on | 59.0062 | 58.8968 | 61.1765 | 65.3269 |
| qlora_on | 59.1033 | 58.8269 | 64.4444 | 62.2834 |
| hybrid_on | 60.7183 | 60.6543 | 61.9883 | 65.3269 |
| few_shot_off | 58.9497 | 58.8200 | 61.5385 | 65.3269 |
| hybrid_off | 60.7183 | 60.6364 | 62.3529 | 65.3269 |

There are 1669 gold aspect assignments and 1678 gold pairs. Only 73 reviews are positive for the held-out aspect (48 negative, 20 neutral, 5 positive sentiment pairs); all 957 reviews still contribute to false-positive counting.

| Paired contrast | Overall pair F1 difference [95% interval], F1 points |
| --- | --- |
| Hybrid-on minus Few-shot-on | +1.7121 [+0.7457, +2.7109] |
| Hybrid-on minus QLoRA-on | +1.6150 [-0.0321, +3.2661] |

| Hybrid-on minus Hybrid-off | 0.0000 [-0.0846, +0.0834] |

Intervals use 2000 complete-review paired percentile-bootstrap draws, seed 20261109. They describe this frozen replay; they do not account for historical selection, between-fold variation or new-business generalisation, and are not presented as significance tests. Different named bootstrap views can have slightly different Monte Carlo endpoints even when their point estimates coincide; no favourable view or seed was selected.

Hybrid has the highest observed overall pair F1, while QLoRA has the highest held-out point estimate. Few-shot-on and Hybrid-on detect identical aspect sets on all 957 reviews. On their same correctly detected aspects, conditional sentiment F1 rises from 90.2028 to 92.8755; this comparison changes the adapter, prompt and sentiment threshold together. QLoRA conditional sentiment F1 94.8246 uses a different selected population and is not a like-for-like sentiment ranking.

For Hybrid-on, 719 of 804 pair false positives arise from absent aspects, and 515 of 596 pair false negatives arise from missed aspects. The remaining 85 false positives and 81 false negatives occur within correctly detected aspects. Detection remains the main error source. Conditional sentiment excludes detection errors and cannot replace end-to-end quality.

## Prefix reuse: speed with observed output differences

| Variant | Off P95 (s) | On P95 (s) | On/off throughput | Changed final review outputs |
| --- | --- | --- | --- | --- |
| few_shot | 3.900 | 1.316 | 3.7359 | 7/957 |
| hybrid | 3.590 | 1.315 | 3.5433 | 6/957 |

Each cache mode was measured once, sequentially, with the same frozen model, prompts, thresholds, input order and engineering settings. The ratios are descriptive local observations, not randomized repeated causal speed estimates. The full replay changes 7 Few-shot outputs (6 aspect-set changes plus 1 sentiment-only change) and 6 Hybrid outputs (all aspect-set changes). Equal aggregate Hybrid F1 therefore does not imply equal predictions or lossless caching.

Both modes differ by as much as 0.2820848 in an aspect score across 11484 comparisons, exceeding the 100-development-review maximum of about 0.121. Scores are restricted-label softmax values, not calibrated probabilities of correctness. Common-selected-aspect sentiment maximum differences are 0.0550284 for Few-shot and 0.00454479 for Hybrid.

In the exploratory CPU inspection after completion, each pipeline adds three false-positive aspects and removes three others, without changing any correctly detected aspect set. The held-out aspect gains one false-positive pair: Few-shot held-out pair F1 changes 61.5385 to 61.1765, and Hybrid 62.3529 to 61.9883. Hybrid sentiment-score differences occur in four reviews whose detected-aspect composition changed; this co-occurrence is not an independent causal diagnosis.

Prefix reuse retains fixed instruction/demonstration KV tensors, not review text or answers. End-of-quality allocated GPU memory is higher by 114.19 MiB for Few-shot and 64.55 MiB for Hybrid; allocator reservation/peak differences are larger and are not identical to retained cache size. See runtime.json for sampled device memory, process allocator counts and their distinct scopes.

## Load, operating point and sustained service

Closed-loop tests keep 1/2/4/8 requests in flight, with three 30-request repeats per setting. More HTTP concurrency mainly adds waiting to the single GPU worker. Median throughput and P95 below are medians of the three repeats, not confidence intervals.

| Variant | C1 reviews/s | C8 reviews/s | C1 P95 (s) | C8 P95 (s) |
| --- | --- | --- | --- | --- |
| few_shot | 1.096 | 1.143 | 1.324 | 8.174 |
| qlora | 0.862 | 0.862 | 1.647 | 10.953 |
| hybrid | 1.122 | 1.131 | 1.362 | 8.343 |

Independent arrivals were tested for 90 seconds, three repeats each, at 25/50/75/100/125% of each pipeline's own frozen C1 median capacity. These fractions are not equal absolute loads. All three pipelines met the illustrative 95%-of-all-attempts-within-two-seconds target in their short 50% runs; at 75%, Few-shot, QLoRA and Hybrid missed it in 2, 1 and 2 repeats respectively. This target was an engineering interpretation, not a contracted SLA.

The matched absolute-rate extension used 0.4308344481 reviews/s for all three variants, with three 90-second runs and matched ordering. Each variant returned 117/117 successful responses. Median P95 was 1.421 s / 1.725 s / 1.369 s for Few-shot / QLoRA / Hybrid; the two-second totals were 114/117, 114/117 and 116/117. At this low offered load, observed throughput mostly reflects arrivals rather than maximum capacity.

| One-hour run | Offered reviews/s | Success/attempts | P95 (s) | All attempts within 2 s | All-run memory samples (MiB) | Range of 5-min maxima (MiB) |
| --- | --- | --- | --- | --- | --- | --- |
| original_70pct | 0.785209 | 2827/2827 | 2.137 | 93.60% | 3508-3815 | 3814-3815 |
| additional_50pct | 0.560863 | 2020/2020 | 1.361 | 97.92% | 3508-3815 | 3814-3815 |

The original 70% soak returned all 2827 requests but its P95 was 2.137 s and only 93.60% of attempts met the two-second budget. After observing that result, a separate 50% one-hour run was registered using the same model, runtime settings, development pool and seed. This additional operating-point choice was made after results were visible; it is not part of the original preregistration or a new blind test. Both outcomes are retained.

The additional run met the illustrative whole-hour target: 97.92% of all attempts completed successfully within two seconds. This supports a candidate starting point for further trials on this machine and input pool, not a production guarantee. Whole-hour success does not guarantee every window or future workload. The two long runs were sequential, with a fresh service start; timing, system state and allocator behaviour remain possible influences.

The twelve five-minute HTTP P95 values ranged 1.854-2.576 s at 70% and 1.311-1.375 s at 50%. These ranges describe window quantiles, not confidence intervals. The additional 50% run still had a P99 of 2.874 s.

Whole-run device memory min-max uses all aligned NVIDIA samples, whereas the last column ranges over the maximum sample within each five-minute window. For the original run these are 3508-3815 MiB versus 3814-3815 MiB; the latter must not be reported as the full memory range. Sampling is approximately every five seconds and is device-wide, including display/other use, not a continuous process peak. Startup has one observation per session, not repeated cold-start evidence. Driver limiting counters and sampled instantaneous flags do not establish a physically isolated thermal cause.

Each long run reuses the same 100 development reviews. Repeated final-label consistency is reported separately from correctness:

## Burst recovery and label-free input monitoring

Three original burst cycles used 60 seconds at 50% capacity, 30 seconds at 200%, then 180 seconds at 50%, without draining between phases. Recovery requires three consecutive scheduled recovery requests to succeed within 1.10 times baseline HTTP P95, with queue wait at most max(100 ms, 1.10 times baseline queue P95). Confirmation time is measured from burst end until those responses have completed.

| Cycle | Burst successes/attempts | Recovery successes/attempts | Confirmed after burst (s) |
| --- | --- | --- | --- |
| 1 | 39/68 | 100/101 | 19.183 |
| 2 | 41/68 | 100/101 | 15.078 |
| 3 | 41/68 | 100/101 | 15.104 |

All three cycles met this observational recovery rule, while burst overload caused 429 rejections and each recovery phase still contained one 429. This is overload recovery, not a process-crash/restart test or a permanent recovery guarantee.

The input experiment sent normal, longest-decile, then normal development reviews for two minutes each. The live observer never read labels. Two complete long-input windows exceeded the fixed JS divergence threshold of 0.1 bits (0.6930 and 0.7394); four complete normal windows remained near 0.0216-0.0261. A seventh, partial drain window also crossed the threshold but contained only one completion and is flagged low-sample. There were no late-attachment backfills or window revisions.

Online windows group completed outcomes; post-run windows group scheduled arrivals. These clocks must not be conflated. Delayed labels are joined only after the run, with first-success deduplication within each phase. The long phase uses only ten unique reviews; phase quality differences reflect changing sample composition and do not establish parameter degradation. Signals from this artificial length shift do not estimate a real production false-alarm rate.

## Final validation

After all GPU campaigns completed, the serving-related CPU suite passed 95 tests
and the existing repository quality gate passed its 83-test CPU suite, Ruff
checks, maintained-interface formatting checks and nine guide-link checks. These
are software checks, not additional model-evaluation samples. The final public
candidate audit scanned 568 text files, including 375 Python files, and reported
zero credential-pattern or publication-boundary candidates within that scanned
scope; ignored private artifacts and Git history were outside this audit.

An independent aggregate review checked 591 fields against private evidence.
All five published data files match the SHA256 values in the manifest, and the
bundle contains only the six files listed above. Original request text, labels,
individual outputs, weights and telemetry remain in the private local study.

No result here establishes a publicly deployed service, customer adoption, business time savings, optimal model size, arbitrary-hardware speed or a production SLA. New business use requires new representative labelled data and network/security/operational validation.
